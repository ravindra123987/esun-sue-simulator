Scale-up Packet Viewer

What you are looking at

Three devices and two 800G cables: XPU A's NIC sends to a switch, which forwards to XPU B's NIC. Each cable end runs its own link-level retry (LLR, UEC 1.1 §5.1) and credit-based flow control (CBFC, §5.2), so the switch is the receiver on hop 1 and the sender on hop 2. Every frame, control block and state on screen is what the simulator (sim/path.py) did.

Using it

Pick a scenario in the sidebar and press Play; the picture stops at each event and the banner says what happened. Click any block to inspect its state, or click a frame anywhere to follow it: it is highlighted wherever it appears, and the Inspector lists its whole journey. Share moment copies a link to the current scenario, view and time.

Live mode

Run python3 tools/live.py in a clone of the repo and open http://127.0.0.1:8765/. The page then runs the simulator a few nanoseconds ahead of what it shows. The sidebar gains fault-injection buttons per hop and a custom-run form. Live mode is local only; the published page offers Recorded.

How the model maps to hardware

XPU A's NIC: an always-full send queue in HBM, the CBFC credit gate, LLR transmit and its replay buffer. Switch port 1: FCS check and LLR receive; accepted frames wait in the ingress buffer, whose size is the credit pool port 1 gives XPU A. Switch port 7: takes the oldest buffered frame when its own LLR window and XPU B's credits allow (which frees XPU A's credits), keeps a copy in a second replay buffer, and sends it on. XPU B's NIC: FCS and LLR receive, a receive buffer, and a DMA engine writing to HBM at a set rate. Control blocks (8 B) ride in fixed slots every 2048 B of link time and are drawn far wider than their true 0.08 ns.

Not modelled

Switch pipeline latency (0 ns), other switch ports, DMA timing out of XPU A's HBM, more than one VC or flow, the PCS-status timer. Recorded runs come from tools/make_traces.py, captions from sim/trace.py.

Live mode needs the simulator

This page is served statically, so there is no simulator behind it. To drive it live, clone the repository and run the server on your machine (Python 3.11 or newer, no packages needed):

git clone https://github.com/ravindra123987/esun-sue-simulator
cd esun-sue-simulator
python3 tools/live.py          # then open http://127.0.0.1:8765/

The page at that address has the Live source enabled, with fault injection and custom runs in the sidebar.
