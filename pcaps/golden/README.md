# Golden captures

Hand-built frames, one packet type or scenario per file, generated by `tools/make_golden.py` from the layers in `sue/`. Every frame's UET CRC is verified before it is written, and again by the Lua dissector in `tests/test_dissector.py`. Expected values per frame (CRC status, recovered PSN and gap, and the field values the dissector must decode) are in [golden.json](golden.json). `tests/test_dissector.py` fails if the committed files differ from what the generator produces. Frames have no Ethernet FCS.

| File | What it shows | Spec |
|---|---|---|
| 01-ufh16-rodl-syn-read | PDC setup: syn=1, PSN on the wire as `{0x00, psn_state}`, one 64 B read, padded to 56 B | UEC Fig 3-68, §3.5.26.1 |
| 02-ufh16-rodl-two-stores | Two packed 256 B stores (ac=0 then ac=1). 556 B with FCS. PSN 1042 is only in the CRC | SUE-T §7.4, UEC §3.4.3.3 |
| 03-ufh16-rodl-table-3-14 | Four packed reads with the address offsets of Table 3-14 (+0x100, −0x300, +0x1EFCE00) | UEC Table 3-14 |
| 04-ufh16-rodl-ext-and-padding | ehl=1 inherited by an ac=1 header; 53 B payload padded to 56; ehl change forces ac=0 | UEC §3.4.3.3 |
| 05-ufh16-ack-four-responses | 20 B ACK + three RC_OK and one RC_BAD_ADDR response + padding = 64 B with FCS. CRC without PSN | UEC Fig 3-120, 3-123 |
| 06-ufh16-ack-read-data | ACK returning two 64 B read responses | UEC Fig 3-28 |
| 07-esun-rodl-two-stores | ESUN header on EtherType 0x88B5 + RODL general header + two stores | ESUN §5.2, UEC Fig 3-67 |
| 08-udp-rodl-two-stores | Ethernet/IPv4/UDP 4793 + RODL general header + two stores; UDP checksum 0 | UEC §3.5.26 |
| 09-ufh16-conversation | syn=1 (PSN 2000), two syn=0 writes (PSN 2001, 2002 hidden), cumulative ACK | UEC §3.5.7.3 |
| 10-ufh16-loss-and-retx | PSN 3002 lost: the dissector recovers 3003 from the CRC (gap 1); then Go-Back-N with retx=1 from 3002 (back 3) | UEC §3.5.7.2, §3.5.22 |
| 11-ufh16-corrupted | One payload bit flipped in PSN 4001: CRC Bad (no PSN in the window matches); tracking continues at 4002 | UEC §3.5.26 |
| 12-ufh16-atomic-and-ack-offset | Packed atomic + fetching atomic (4 B atomic header each) + write; ACK with ack_psn_offset = −1 | UEC §3.4.3.5, §3.5.11.4.5 |

Open them with the dissector:

```
tshark -X lua_script:wireshark/sue.lua -r pcaps/golden/09-ufh16-conversation.pcap
```

For single-frame syn=0 captures (02–04) the dissector has not seen a syn for that PDC, so it shows the CRC as Unverified. Pass the PSN to check it: `-o sue.assume_psn:1042`.

Project decisions baked into these frames (ESUN EtherType, CRC byte order, hidden-PSN placement, …) are listed in [docs/findings/m1-decisions.md](../../docs/findings/m1-decisions.md).
